## Upstream changes that shaped this rebase

- **`ServerArgs` is a msgspec record.** `server_args.py` no longer declares fields: `ServerArgs` is built by
  `msgspec.defstruct` from the per-group field classes in `arg_groups/fields/*` (`Serving`, `Parallel`,
  `Device`, …). Field metadata rides on `Annotated[T, Arg(...)]` (`Arg` is a frozen msgspec Struct in
  `arg_groups/arg_utils.py`); `record_fields`/`resolvable_fields` enumerate them. Resolution hooks live in
  `arg_groups/*_hook.py` and write through `declare_resolution(server_args, source, **fields)`;
  `ServerArgs._handle_amd_specifics` is now `arg_groups/platform_hook.handle_amd_specifics`. Readbacks
  (engine log line, `/server_info`, gRPC `get_server_info`, the scheduler's
  `get_context().resolved_server_args_dict()`, the tokenizer manager's request-dump snapshot) all go
  through `server_args.resolved_dict()`. Layers read `get_parallel().dcp_size` / `.nnodes`,
  `get_serving().host`, and `ParallelState.attn_tp_size` (`distributed/parallel_state_wrapper.py`).
  Patches 086, 088, 096 are re-anchored on this.
- **gfx1250 support landed upstream.** Upstream added the fp32 P·V / K-upcast branches under
  `IS_GFX1250` in `decode_attention.py` (the exact form of our 011), a gfx1250 `num_stages` block in the FP8
  block-GEMM config (005), a gfx1250 MXFP4 shuffle layout (060), `is_gfx1250_supported` (027), gfx1250 in the
  kernel-build targets (008, where the topk shared-memory default also dropped to 40 KB for non-gfx942;
  RDNA4 keeps 48 KB). RDNA4 is still not detected anywhere upstream, so every gfx12 patch stays; the
  gfx1201 branches now sit in the `else` of the gfx1250 conditionals (011, 087).
- **Split-KV tree verify and shared-KV** (`use_verify_splitkv`) are still gfx95-only upstream (065 unchanged
  in substance).
- **EVS video.** `EVSDataItem` was removed; EVS items are recognised by `model_specific_data["thw_grids"]`
  (057 re-anchored; the combined-path routing is still needed — upstream's condition is still offset-only).
- **Weight loading.** `sharded_weight_loader`'s `override_tp_rank` became upstream's `tp_rank_getter`; the
  Qwen3.5 `replicate_mlp` hunks are re-anchored on `_QWEN3_5_MOE_TEXT_MODEL_TYPES` / `_finish_mlp_output`
  (001).
- **Communicators.** `LayerCommunicator` grew `_is_sp_variant` and a LayerNorm-SP sibling; 080's
  `hip_fp32_allreduce` kwarg is propagated to both (080).
- **Batch-invariant matmul.** `_matmul_persistent_triton(a, b, out_dtype, bias)` now indexes its configs by
  `a.dtype` (094).
- **`moe_fused_gate(scores, bias: Optional)`** asserts `bias is None` only on the softmax path, so the
  None-bias zeros guard (097) is still required for the fused-router path.
- **`--cuda-graph-max-bs`** is a deprecated alias of `--cuda-graph-max-bs-decode` (already so in v0.5.18;
  the `qwen38` preset now passes the new name).
- transformers stays at 5.12.1 and `hf_transformers/common.py` still registers the
  `_Gemma4UnifiedConfigAlias`, so 098 is still required (applied unchanged).

## Series transition: 70 → 70

Independent dry-run of the v0.5.18 series on pristine v0.5.20 (each patch `git apply --check`ed alone):
**38 applied clean, 32 failed** — 10 of those only because they depend on an earlier patch
(044, 045, 056, 061, 077, 079, 081, 082, 093, 095). Sequential rebase result: **47 unchanged, 23
regenerated** (001, 004, 005, 008, 011, 027, 033, 046, 049, 057, 060, 065, 073, 074, 080, 086, 087, 088,
089, 090, 094, 096, 097). No patch was dropped or added. 073 applied *cleanly* and was first recorded as
unchanged; it is the one patch whose clean hunk became wrong on v0.5.20 (see below). Regenerated patches were produced with
`git diff <commit>^ <commit>` from the per-patch commits in the rebase worktree; unchanged patches keep
their original files byte-for-byte.

### Hunk-level upstreaming (dropped during rebase; patch retained)

- `011`: the gfx1250 branches carry upstream's copy of the fp32 P·V / K-upcast; the patch now applies the
  same form to the non-gfx1250 (RDNA4) branches only.
- `049`: hunk 1 (`_causal_conv1d_fwd_kernel` column-load cast) is upstream as `.to(x_elem_ty)`; the
  update-kernel hunk is retained.
- `073`: **clean apply, broken result.** The hunk adds `and (is_cuda() or is_musa() or is_npu())` to
  `_mamba_radix_cache_resolution`, and it still applied byte-for-byte — but v0.5.20's `overrides.py` no
  longer imports those helpers (it only imports `get_context, get_platform` and four `utils.common`
  helpers), so every Mamba/DeltaNet hybrid preset would have died at `publish()` with
  `NameError: name 'is_cuda' is not defined`. Rewritten to the file's own style:
  `get_platform().is_cuda or get_platform().is_musa or get_platform().is_npu` (`PlatformContext`
  booleans). Verified offline: qwen38 resolves `mamba_radix_cache_strategy = no_buffer` on HIP, the same
  value v0.5.18 produced. Caught by the secure-launch resolver test, *not* by the first pyflakes pass —
  that pass had been run with the new env's interpreter, which has no `pyflakes` module, and the
  "0 undefined names" came from grepping an import error. The corrected scan is below.
- `074`: compressed-tensors `kv_cache_scheme` loading and its unit test are upstream (#35455); the Laguna
  k/v-scale remap hunks are retained.
- `096`: readbacks already flow through `resolved_dict()`; the sensitive-field mechanism was redesigned for
  the msgspec record (below). All seven `STRICT_PATCHES` markers are intact.
